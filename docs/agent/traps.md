# Traps

- `npm run lint` ahora corre (antes fallaba por falta de `eslint.config.js`). Las reglas heredadas (`no-unused-vars`, `no-useless-escape`, `no-empty`) están como `warn` por deuda previa (147 avisos); el código nuevo debe quedar en 0. Evidencia: `eslint.config.js`.
- Los tests corren con Vitest + jsdom (`npm test`); el setup está en `src/test/setup.ts`. `vite.config.ts` importa `defineConfig` de `vitest/config`.
- Rangos y zona horaria: el panel manda días locales (`from`/`to`) y la zona; el servidor los convierte a `[from, to)` UTC. No armar límites UTC en el cliente. Evidencia: `src/pages/acquisition/utils/filters.ts`.
- Cada reporte carga y falla por separado (`useReport`): error ≠ vacío ≠ cargando ≠ datos viejos. Un refresh fallido conserva los datos marcados como obsoletos; nuevos filtros los descartan. Las respuestas de pedidos reemplazados se ignoran.
- El polling de "Actividad reciente" (15 s) se pausa con la pestaña oculta y refresca al volver. Evidencia: `src/pages/acquisition/hooks/useLiveAcquisition.ts`.
- Campaña, fuente y medio vienen de la URL del visitante: renderizarlos siempre como texto, nunca como HTML. Los IDs de visita se muestran abreviados (8 caracteres) y el `visitorId` nunca llega al panel.
- El API responde 400 si el rango supera 92 días o el año sale de 1900–2100, o si `channel` no es un canal real: `parseFilters`/`applyPatch` ya lo impiden (los selectores de fecha acotan el otro extremo). Evidencia: `src/pages/acquisition/utils/filters.ts`.
- `useReport(load, key, enabled, scope)`: un `scope` nuevo (filtros) descarta los datos; una `key` nueva dentro del mismo scope (otra página, otra ventana en vivo) los conserva mientras carga, para no perder foco ni scroll. Reintentar sin datos es una carga completa, no una tarjeta en blanco.
- Los estados "vacío" tienen en cuenta las conversiones sin recorrido enlazable: sin canales pero con `unlinked` se muestra la tabla. El refresco periódico de "Actividad reciente" no cuenta como refresco del usuario.
- `status` de mensajes: el enum admite `delivered`/`read`, pero el webhook de estados solo registra fallas y nunca actualiza salientes; solo `failed` es confiable. No mostrar "entregado" ni "leído". Evidencia: `api/models/ConversationMessage.ts:25`, `api/controllers/notification/whatsapp-controller.ts:114-120`.
- FAQ y cursos solo alimentan a Mila en WhatsApp; Instagram responde únicamente con bloques cuya frase coincide. Evidencia: `api/services/gemini-service.ts`.
- `npm run typecheck` ya fallaba antes de agregarlo (48 errores heredados en `tsconfig.json`, ninguno en `bot-message/`); por eso chequea primero `tsconfig.e2e.json`. El build usa Vite sin `tsc`. El código nuevo no debe sumar errores.
- Fuera de Mensajes no hay error boundary: una forma inesperada del API deja el panel en blanco. Mensajes usa `SectionErrorBoundary` por pestaña y normaliza las respuestas (`toChatSummaries`, `toChatMessages`) descartando filas rotas.
- El API falso de `e2e/` responde 404 a toda ruta, método o query string que no esté en `answer()` y el test falla: una llamada nueva del admin debe agregarse ahí a propósito. Datos compartidos: `src/test/fixtures/botMessage.ts`.
- Respuestas viejas: `useChatThread` guarda la conversación actual en un ref y descarta mensajes o recargas de otra; el borrador solo se limpia si se envió desde el chat que sigue abierto. Evidencia: `hooks/useChatThread/index.ts`.
- Headless UI (`GlobalModal`) traba su animación en jsdom con el runner cargado: los tests de pestañas mockean `GlobalModal` con un diálogo sin animación. Evidencia: `BotMessagePage.test.tsx`.
- Instagram con solo comentarios: el composer se deshabilita con explicación (Meta rechazaría el envío). Se decide con los mensajes cargados: hace falta un DM entrante sin `kind`.
- Timers falsos en tests de polling: activarlos antes del `render` (`useFakeTimers({ shouldAdvanceTime: true })` + `userEvent.setup({ advanceTimers })`); si no, el intervalo ya creado nunca corre. Evidencia: `BotMessagePage.test.tsx`.
- Un comentario aparece en el chat de quien comenta, pero el admin no puede responderle manualmente hasta que escriba un DM (el comentario no abre la ventana de mensajería). Evidencia: `api/docs/agent/traps.md`.
- `SectionErrorBoundary` es una clase porque React no admite boundaries como función: no convertirla. La Bandeja queda montada y se reintenta con `resetKey` al cambiar de pestaña. Evidencia: `components/SectionErrorBoundary/index.tsx`.
- e2e: la raíz del diálogo de Headless UI mide 0 px (hijos `fixed`) y Playwright la ve "hidden": verificar el botón o el título de adentro. Evidencia: `e2e/chat.spec.ts`.
- Respuesta fija: el modal tiene scroll propio, así que `fullPage` no muestra su parte baja; las capturas hacen scroll al elemento. Se cuentan code points como la API (un emoji simple es 1; con tono de piel o familia, más) y hasta 1000 bytes: validar con `fixedReplyIssue`, no con `.length`. Un texto fijo largo guardado bloquea Guardar también en modo Gemini, porque la API lo valida siempre. Evidencia: `e2e/screenshots.spec.ts`, `utils/fixedReply.ts`.
- Plantillas: Meta devuelve una fila por idioma con el mismo `name`; la clave es `id` y "Probar" usa el idioma de esa tarjeta. Borrar es por nombre (todos los idiomas). Evidencia: `utils/templates.ts`.
- Cupones: `endsAt` se envía como el último instante del día local elegido y `startsAt` como el primero, para que el cupón rija todo el último día. Los usos por día llegan como `YYYY-MM-DD` ya en hora de Tucumán: no pasarlos por `new Date`. Evidencia: `src/pages/coupons/utils/format.ts`.
- Scroll lateral en celular: quien scrollea es el `<main>` de `AdminLayout`, no el documento; medir solo `document` no lo detecta. Causas típicas: `grid` sin `grid-cols-1` (la columna implícita crece con el contenido), `sr-only` en una tabla con `overflow-x-auto` sin `relative`, y popovers `invisible` (ocupan ancho; usar `hidden`). No taparlo con `overflow-x-hidden`. Evidencia: `e2e/mobile-layout.spec.ts`.
- `InfoTip` se ancla al ancestro `relative` más cercano desde `sm`: la tarjeta que lo use debe ser `relative`. Evidencia: `OverviewCards`.
- `stacked-table` cambia `display`, que en algunos lectores borra la semántica de tabla: por eso llevan `role` explícito (`table`, `row`, `cell`…). No quitarlos. Evidencia: `src/index.css`.
